Complete methodology — Parts A–L

Part A — Purpose and scope

GridVision builds a digital model of the BZ0109 low-voltage network and runs a quasi-static time series (QSTS) every 15 minutes for a chosen day.

Questions answered

  • Transformer net power (import vs export) vs the measured load profile (LP)
  • Phase voltages at poles (measured where meters exist, simulated everywhere)
  • Loading of the transformer and voltage risk vs 216.2 V – 243.8 V (nominal ~230 V)

Not in scope: electromechanical transients; fault currents; protection coordination; live SCADA control.

Ratings (this case)

  • Transformer capacity: 250 kVA (typical options: 100 / 160 / 250 / 400 / 630 kVA)
  • Nominal LV: ~230 V phase-to-neutral / ~400 V line-to-line
  • App voltage band: 216.2 V – 243.8 V
  • Time steps: 96 per day (15 min)

Preparation rules

  • Match accounts after stripping leading zeros
  • Parse billing by column headers (not fixed positions)
  • Billing cycle codes (e.g. 202506, 202512) identify monthly energy columns
  • Same account in billing + solar ⇒ net-metered

Part C — Network topology

  1. Poles = nodes; lines = edges
  2. Transformer pole = source (distance 0 m)
  3. Each first hop from the TF starts a feeder (F1, F2, …)
  4. BFS labels every downstream pole with one feeder (radial LV)
  5. Distance d = path length along lines from TF (m); geographic fallback if a GIS edge is missing
d(TF) = 0
d(k) = Σ length on path TF → k

Part D — Tariff categories, load models, shapes

Default mapping

TariffLoad modelTypical daily behaviour
R1, R2, D1Constant currentResidential: evening peak
GP11, GP12, GP1-GConstant currentMore daytime commercial
STL1, STL2Constant currentHigher after dark
I12Constant powerIndustrial / flatter or shift-based

Load model meaning

  • Constant power: P fixed ⇒ I ≈ P/V (current rises if V falls)
  • Constant current: I roughly fixed ⇒ P ∝ V (milder drop feedback)

Future tariffs: default to constant current unless clearly industrial; UI may allow override.

From monthly energy to power

P_avg,c = E_month,c / (N_days × 24)

Shaped customer load

P_c(t) = P_avg,c · s_tariff(c)(t) · α(t)
  • s_tariff: normalised shape (96 steps/day; weekday / weekend / holiday can differ)
  • α(t): global day/night scale so the sum of loads can track the measured TF day

Total load

P_load(t) = P_base + Σ_c P_c(t)

P_base: optional unmetered / loss / overnight floor.

Phase allocation: single-phase customers may sit on A, B, or C; three-phase where applicable. Unknown phases are assigned so the feeder is not artificially perfectly balanced.

Part E — Solar and net-metering

P_pv,i(t) = P_inv,i · c_irr(t) · β
P_pv(t) = Σ_i P_pv,i(t)
  • c_irr(t): daytime irradiance-like curve (~0 at night, peak near solar noon)
  • β: export / calibration scale

Net-metered (same account in billing + solar): meter = import − export. Gross load is reconstructed conceptually so PV is not ignored:

P_gross ≈ P_net + P_inv · CF · σ
  • CF (Sri Lanka rooftop) ≈ 14–18% annual
  • σ = self-consumption fraction (lower ⇒ more noon export)

Part F — Power-flow calculation and balancing (core procedure)

This is the electrical heart of the methodology.

F1. What “power flow” means here

At one time t, the network is treated as steady-state:

  • Known (or assumed) voltages at the source (TF LV bus)
  • Known load and PV injections at poles
  • Lines with impedance
  • Solve for branch currents, pole voltages, and power through the transformer

QSTS = repeat that steady solve (or an equivalent estimate) 96 times per day.

F2. Power balance at the transformer (global balance)

All active power must balance at the LV study boundary (ignoring storage):

P_TF,net(t) + P_pv(t) = P_load(t) + P_loss(t)

P_TF,net(t) ≈ P_load(t) − P_pv(t) + P_loss(t)
(import positive into LV)

Interpretation

SituationBalanceP_TF,net
Evening peak, no PVLoad supplied from MVImport > 0
High noon PVPV supplies loads; surplus leaves LVExport < 0
Light load, no PVSmall importSmall positive
  • Losses P_loss are usually a few percent of throughput; some simplified UI paths fold them into residual calibration rather than computing every branch I²R.
  • Reactive power (detailed OpenDSS): a similar balance exists for Q; loads may use pf ≈ 0.95. Many planning displays focus on P and |V|.

F3. Step-by-step power-flow procedure (one time step t)

Step 1 — Fix the study time
Pick t (e.g. 19:00). All shapes and meters refer to that interval.

Step 2 — Assemble nodal injections

P_k^inj(t) = P_pv,k(t) − P_load,k(t)
  • PV = positive injection into the node
  • Load = withdrawal
  • Three-phase: split by A/B/C if single-phase customers are phase-allocated

Step 3 — Set the source boundary (slack bus)
Transformer LV bus is the slack / reference:

  • |V_TF(t)| from measurement if available, else nominal (~230 V phase-neutral / 400 V line-line)
  • Angle reference 0
  • TF supplies whatever P+jQ is needed to close the balance (rating checked afterwards)

Step 4 — Line electrical model
Preferred (4-wire LV):

[Va Vb Vc Vn]^T = Z_4×4 · [Ia Ib Ic In]^T
(primitive impedance including neutral and mutual terms)

ΔV_branch ≈ Z_branch · I_branch

Simplified 3-wire omits neutral → less accurate for unbalance.

Step 5 — Load electrical model at nodes

Constant power (e.g. I12):
  S = P+jQ = fixed  ⇒  I = (S/V)*

Constant current (most domestic/GP tariffs):
  I ≈ fixed model  ⇒  P ≈ |V||I|cosφ

Iterate if using full nonlinear power flow (powers depend on voltages).

Step 6 — Solve the network equations
Full OpenDSS-style Newton / fixed-point power flow:

  1. Initialise voltages (e.g. all equal to V_TF)
  2. From voltages, compute load and PV currents
  3. Apply KCL at each node (currents sum to zero with branch currents)
  4. Update voltages from Z, I
  5. Repeat until power mismatches and voltage changes are small

Outputs: V_k,φ(t), branch currents, P_TF,net(t), losses, phase unbalance.

Calibrated radial estimate (UI path when full solve is not run):

  1. Compute fleet P_load(t), P_pv(t)
  2. Form P_sim,raw(t) = P_load − P_pv (+ residual/scale — Part G)
  3. Approximate voltage along path: V_k(t) ≈ V_TF(t) − ΔV(d_k, P_TF,net(t), P_downstream,k)
  4. Under export, ΔV can reverse → remote voltage rise

This preserves topology + distance + measured TF power shape for maps and distance–voltage plots.

Step 7 — Local and global checks (balancing verification)

Global: P_TF,net ≈ P_load − P_pv + P_loss
Local: line powers + load − PV ≈ 0
Phase: Ia + Ib + Ic + In ≈ 0
Thermal/voltage: |P_TF| vs S_rated; V vs 216.2 / 243.8 V

F4. Balancing through the day

Night / early morning: PV ≈ 0 → P_TF,net ≈ P_load + P_loss → import. Currents TF → feeders. Voltage generally drops with distance.

Solar noon: P_pv large → if P_pv > P_load + P_loss → export. Current can flow feeders → TF → MV. Voltage at PV-rich remote poles can rise.

Evening peak: PV ≈ 0, residential/GP peaks → maximum import, often minimum remote voltage, highest TF loading %.

Always: generation + import = load + export + losses (import/export = TF terminal net exchange with MV).

F5. Transformer loading after the solve

L% ≈ |P_TF,net| / S_rated × 100
If Q known: L% = |S_TF| / S_rated × 100

Part G — Matching the measured meter (calibration)

Measured LP: P_meas(t).

P_sim,raw(t) = P_load(t) − P_pv(t)
P_sim(t) = α(t) · P_sim,raw(t) + r(t)

Day/night α and residual r reduce error vs P_meas.

Export-target (locked)

P_pv*(t) = max(P_load(t) − P_meas(t), 0)

Allocate P_pv* proportional to inverter ratings, then re-solve / re-estimate voltages.

Use: match a real measured day. For pure what-if hosting studies: drive PV by irradiance × inverter only (export-target off).

Metrics

corr = corrcoef(P_meas, P_sim)
RMSE_kW = √ mean((P_sim − P_meas)²)
RMSE_V  = √ mean((V_sim − V_meas)²)
PatternLikely issue
High corr, high RMSEScale / magnitude
Low corrWrong peak or solar timing (shapes)
Good power, bad voltageImpedance, phase allocation, or V_TF

Part H — QSTS procedure (full day)

For each t ∈ {00:00, 00:15, …, 23:45}:

  1. Build P_c(t) from tariff shapes and scales
  2. Build P_pv(t) (shape or export-target)
  3. Power balance + power flow (Part F)
  4. Store P_sim, V_k,φ, L%
  • Peak snapshot: max import
  • Solar-noon snapshot: min net / max export

Part J — End-to-end procedure (operator + algorithm)

  1. Load GIS → topology, feeders, distances
  2. Load DATA → pole placement, tariff → model + shape, P_avg
  3. Load LP → P_meas(t), study day, sparse V_meas
  4. Load solar → PV size, net-meter flags
  5. For each 15-min step: assemble loads & PV; enforce power balance / run power flow; calibrate to meter if required; save voltages and TF power
  6. Compute corr, RMSE, peak, noon
  7. Display charts, tables, distance plot, map

Part L — Limitations

  • Shapes are by tariff class, not every customer’s true 15-min meter
  • Export-target matches the meter strongly; use irradiance-only PV for pure what-if studies
  • Simplified radial voltage is not a full unbalanced 4-wire legal audit
  • Q and exact losses may be approximated
